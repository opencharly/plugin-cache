# 2026.266.1435 — feat(cache): charly cache push/pull — the OCI-transport operator surface

## Summary

Adds the operator face of the cache's registry transport: **`charly cache push <name> <ref>`** pushes a named `spec/cache.ArtifactStore` (an OCI Image Layout) to a registry, and **`charly cache pull <name> <ref>`** pulls one back into its local layout.

The transport itself lives in **candy/plugin-oci** (`verb:oci cache-push`/`cache-pull`, merged in **plugin-oci#4**) — the go-containerregistry stack stays single-homed there, never linked into this command plugin or into core. These leaves build the **`spec.CacheTransferRequest`** envelope and reach it over the F10 peer-dispatch leg (`InvokeProvider "verb"/"oci"`), exactly like candy/plugin-box reaches `verb:oci` for its merge. **The wire pair is CUE single-sourced in `spec/schema/oci.cue`** (`#CacheTransferRequest`/`#CacheTransferReply`, **spec#149**, tag `v0.2026266.1306`), so both plugins share ONE generated type — no hand-written copy to drift (R3/SDD). The command's `ctx` is threaded into the dispatch, and the named cache's directory is resolved via `spec/cache.StoreDir`.

**Files (6):** `cache_oci.go` (new: `CachePushCmd`/`CachePullCmd` + `transferCache`/`transferCacheWith`), `cache_oci_test.go` (new), `plugin.go` (`CacheCmd` gains `push`/`pull`; the in-proc `Invoke` recovers the reverse channel via `ExecutorForInvoke` and threads it; `CliMain` passes nil), `candy/plugin-cache/charly.yml` (description + a runtime-context `charly cache push --help` ADE check), `go.mod` + `go.sum` (bump `spec` → `v0.2026266.1306`, `sdk` → `v0.2026266.1111`).

Deterministic coverage that fails without the change (`cache_oci_test.go`):
- **`TestTransferCacheRealDispatch`** — drives the REAL shipped dispatch: an in-proc `sdk.Executor` (built from a stub executor client) is threaded on ctx, `transferCache` resolves it via `ExecutorForInvoke`, and the real `Executor.InvokeProvider("verb","oci",OpRun,…)` runs — no stub at the transferCache seam, so a broken shipped dispatch fails this test.
- `TestTransferCacheSuccessPath` — the envelope-build → dispatch → reply decode → summary path over an injected seam.
- `TestCachePushRejectsMissingLayout` — a push with no local layout fails via the StoreDir-existence guard (non-nil executor, so it reaches `os.Stat`).
- `TestTransferCacheRequiresReverseChannel` — a nil executor fails the transfer loudly (out-of-process cannot reach `verb:oci`).
- `TestCacheCommandTreeHasOCISurface` — `push`/`pull` parse in the `charly cache` grammar.

**Hard cross-repo dependency, stated explicitly:** this live run's host binary rides **charly#634**, which is OPEN (not merged). The changed leaves depend at runtime on that host supplying the in-proc reverse channel (`sdk.ExecutorForInvoke` → `exec.InvokeProvider`). Because the host is an unmerged sibling branch, this run does **not** establish the state that ships from the pinned `sdk`/`spec` — so the tier is `analysed on a live system`, not `fully tested and validated`, until charly#634 (or its successor) merges and the run is repeated on the merged state. The dispatch LAYER is deterministically locked by `TestTransferCacheRealDispatch` (the real `InvokeProvider` runs, over an in-proc executor), so a broken shipped dispatch fails CI even before charly#634 merges; plugin-oci's transport is live-proven on merged refs in plugin-oci#4.
