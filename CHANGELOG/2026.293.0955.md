# 2026.293.0955 — fix(skills): the cache body moves BESIDE its candy, where the loader actually reads it

## Summary

Moves `.agents/skills/cache/SKILL.md` to `candy/plugin-cache/.agents/skills/cache/SKILL.md` — **beside the candy that owns the skill**, which is the directory the loader reads.

**Why.** `sdk/deploykit/skills_collect.go` resolves the tree as `filepath.Join(layer.GetSourceDir(), ".agents/skills")`, and `GetSourceDir()` is the owning candy's directory. This skill's node is declared in `candy/plugin-cache/charly.yml`, so the loader looks in `candy/plugin-cache/.agents/skills/`. The body was left at the repository root, where nothing reads it — and because the earlier migration also removed the inline `content:`, the node had **no body at all** at build time.

This is a **pure move**: the SKILL.md content is unchanged and the manifest is untouched. The diff is **0 insertions and 0 deletions** — a rename, `{.agents => candy/plugin-cache/.agents}/skills/cache/SKILL.md`.
