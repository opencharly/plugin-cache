# 2026.279.1140 — fix(cache): `charly cache clear`/`refresh` purge the on-disk fetched-repo cache (charly#804)

## Summary

`charly box validate` false-reddens a CLEAN tree on a host whose `~/.cache/charly/repos` holds stale fetched plugin repos — candies fetched at an OLD pinned version whose manifest uses a retired schema shape (opencharly/charly#804).

One named deliverable of `#804` is that **`charly cache clear` is incomplete**: it dropped only the ref answer index (`refs.GitClient.ClearCache`), **not the on-disk fetched-repo TREES**. So a stale pre-SDD candy survived a "clear" and the next scan/validate still tripped on it — exactly the "#804 `charly cache clear` → still ≥1 error" repro.

This bounds the fix to `plugin-cache`:

- **`clearRepoCache()`** removes the whole remote-repo cache directory (`refs.RepoCacheDir()` → `$CHARLY_REPO_CACHE` / `~/.cache/charly/repos`), which holds both the pristine fetched trees and their schema-keyed `.view.<identity>` derived views. An absent dir is a clean no-op.
- **`charly cache clear` and `charly cache refresh`** now call it after clearing the ref index, so a stale fetched candy cannot survive a clear.
