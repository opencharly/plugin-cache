# 2026.270.1314 — fix(cache)!: ship a self-contained CUE schema (no schema-less plugin)

## Summary

Restore `plugin-cache`'s **own self-contained CUE schema** — the schema-less-plugin R5 cutover
tracked in **opencharly/charly#712** (the SDK contract landed as
**opencharly/sdk#314**). `NewMeta` passed a `nil` schema FS and served an **EMPTY**
schema — the SDK's former *"input-less plugin"* waiver. There is no schema-less plugin:
every plugin presents the same CUE declaration surface, even where a capability's authored
input is its pass-through CLI grammar (or a structured wire envelope) rather than an
authored `plugin_input`.

### Files

- `candy/plugin-cache/schema/cache.cue` — the plugin's OWN self-contained schema (`#CachePlugin`), documenting
  `command:cache`. It references no base def, so it compiles **standalone** and splices
  `base ++ plugin` at the host load gate (`charly/charly/plugin_loader.go`
  `registerPluginUnitSchema`).
- `candy/plugin-cache/plugin.go` — `//go:embed schema/*.cue` + `sdk.NewMeta(calver, caps, schemaFS)`
  replaces the trailing `nil`; the stale schema-less comment is corrected.
- `schema_splice_test.go` (NEW, alongside `candy/plugin-cache/schema/cache.cue`) — executes the **real** host
  schema load gate: it loads the SAME base schema FS charly loads
  (`github.com/opencharly/spec/schema`), concatenates through the SAME
  `spec/schemaconcat` contract, compiles `base ++ plugin` with the SAME
  `cuecontext.New()` that `compileBasePlusServed` uses, and asserts `#CachePlugin`
  resolves to a struct. It FAILS without this change (the served schema was empty, so
  `#CachePlugin` was undefined).
- `schema_serve_test.go` — existing: `Describe` must serve a non-empty `schema_cue`
  carrying `#CachePlugin` (also fails without the change).

**Refs:** opencharly/charly#712
